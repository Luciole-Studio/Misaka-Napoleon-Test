# 第二阶段规范：按书稿章节补写

## 背景
用户要求把草稿（原报告）中成书遗漏或压缩的内容**一个不漏**补回成书；**成书已更正过的地方保留成书的更正**，草稿原说法进脚注注明。第一阶段已逐行清点草稿，台账在 `ledger/`。你负责**一个书稿章文件**，把分配给它的全部台账条目写进去。

## 文件（均在 `/Users/makiko/Documents/exam/final/` 下）
- 你要改的书稿：`r_5b1357a9c6-revised/chapters/<你的章>.md`。**只改这一个文件。**其他章同时有别的写手在改。
- 你的工作包：`r_5b1357a9c6-revised/audit/20260926_草稿补回/packets/<你的章>.jsonl`（每行一条台账记录，已按插入位置排序；字段含义见 `SPEC_1_逐行清点.md`）。
- 草稿原文：`r_5b1357a9c6-report/<draft_file>` 第 `draft_line` 行。**每条都要回读草稿原行**；台账的 `missing` 只告诉你缺什么，措辞、数字、引语、出处以草稿原文为准。
- 书稿快照（补写前，台账里的 `anchor`、`book_refs` 行号都指快照）：`r_5b1357a9c6-revised-backup-20260926-003436/chapters/`。你的章改动后行号会漂移，按标题和段落文字定位。
- `KNOWN_ISSUES.md`：成书的有意更正与已知错误。
- 校验：`python3 validate_book.py <章前缀>`（前缀取文件名前三个字符：`00_` `01_` `02a` `02b` `03_` … `10_`）。

## 写法（与全书一致）
1. **文体**：书稿是面向外部读者的中文历史论述。成段写，不用【锚】【机制】【推演】标签；但保留三者的区别，用措辞体现（"文书显示……""可比的先例是……，适用条件是……""据此推断……，把握中等"）。关键结论可加粗，像书中已有段落那样。
2. **一个不漏**：台账 `missing` 列出的每一项（事实、数字、区间、日期、人名、原文引语、出处、置信度、条件、分支、备选结论、改判证据）都要落到正文或脚注里。可以改写、合并、调整次序，不可以把具体内容概括掉。表格按原表恢复为 Markdown 表（每行列数一致），前面加一句引导语。
3. **不用研究代号**：正文不出现卡片代号（F2、P6、S2本义、路径B、K1、M-B1、B7、C12、E1—E7……）、工作区路径、Sister／Last Order 等运行角色名。先看书中对同一概念的叫法（例如书中把"史实打到提尔西特再切换"称作"1807年条件主线"）；书中没有的，第一次出现时用平实中文命名并解释，可在脚注注明"原报告称'路径B'"。研究过程内容（独立审查意见、验收、方法契约、访问状态等）照样补回，写成"研究过程中的独立审查指出……"这类表述，通常放在资料附编。
4. **数字与引语**：数字、区间、单位原样保留（格式可改成书中写法，如1,400万、1803年11月19日）；外文原句保留原文并附中文意译，如书中做法。
5. **脚注**：每个补回的段落或表格至少带一个脚注，写明草稿所列出处（作者、书名、页码、日期、档案系列；草稿说"转引""回溯性""未亲阅"的照录），末尾加"据原报告第X章补回"。草稿对某个说法只给出项目模型或推演、没有史料的，脚注写"本项目模型推算／推演（原报告第X章），非史料记载"。
   - 脚注键用本章新前缀加序号，从1起：00→`草导`，01→`草法`，02a→`草英`，02b→`草海`，03→`草欧`，04→`草南`，05→`草美`，06→`草东`，07→`草省`，08→`草经`，09→`草终`，10→`草资`。
   - 调用与定义的写法照本章已有格式：用〔〕的章写 `〔草法1〕`，定义行以 `〔草法1〕` 开头；02a、02b 的定义写 `- **[草英1]** …`，调用写 `[草英1]`；03、04 的旧注是数字，新注一律用〔草欧N〕〔草南N〕形式（定义行以〔草欧N〕开头）。定义统一追加到本章注释区末尾。
6. **更正（verdict=corrected）**：书稿正文保留书稿版本；在相应句子加脚注："原报告作……（依据……）；本书据……改为……。"该条若另有 `missing`，照常补回。
7. **书稿错误（verdict=book_wrong）**：把书稿错句改正为草稿／证据所示的正确版本，并加脚注说明原书稿写法和改正依据。只处理台账标为 book_wrong 的条目，不要顺手改别的。
8. **判断分歧**（草稿的主线判断与书稿不同，但不是事实错误）：书稿若已说明改判理由，正文保留书稿判断，草稿判断连同其数字和理由写入脚注；书稿若只是没写，把草稿的判断作为明确标注的"另一种估计"补入正文，写清它的条件、数字和把握，不要悄悄替换书稿主线。
9. **前后不矛盾**：补回内容若与附近书稿句子冲突（例如书中说"不照抄日历"而你补回逐年骨架年表），对那句书稿作最小修改使全章自洽，并在 placements 中记为 `adjusted_book_text`，写明原句。
10. **去重**：不同切片的多条台账可能指向同一内容，合并成一次补写，各条都登记到同一位置。
11. **结构**：可以在已有 `##` 下新增 `###` 小节（00章的标题层级在构建时会整体上调一级，照本章已有写法）；不新增章文件，不新增 `#` 级标题；不删除书稿已有内容（第7、9条除外）。

## 完成要求
- 工作包中每一条都要处理。完成后写 `placements/<你的章>.jsonl`，每条工作包记录对应一行：
  `{"draft_file":…, "draft_line":…, "part":…, "status":"inserted|footnoted|fixed|merged|adjusted_book_text|skipped", "where":"所在标题 + 补写段首二十字", "note_keys":["草欧3",…], "note":"…"}`
  `skipped` 只用于核实后确认书稿已有（台账误判），`note` 里给出书稿现行文字作证据。
- 跑 `python3 validate_book.py <章前缀>`，直到本章 0 个 blocking problem（别章的问题不用管）。
- 写 `placements/<你的章>_summary.md`：各状态计数、新增字数（补写前后 `wc -m` 对比）、新增小节列表、所有 adjusted_book_text 与 book_wrong 修改的原句与新句、仍拿不准的地方。
- 上下文管理：先读工作包和本章结构，再按插入位置从后往前或分批处理；每完成一批就写盘。书稿文件大时用 offset/limit 读。
- 完成后回报：本章新增字数、各状态计数、三行要点。
